# 积分系统试运营操作手册

本文面向试运营期间的管理员、队长主管和财务同事，目标是把每天/每周的操作流程跑顺。系统不会自动修复业务数据，所有积分入账、作废、扣分和奖金测算都需要人工确认。

## 一、试运营前准备

1. 确认系统可登录：管理员、队长主管、财务、普通队长账号均可进入对应首页。
2. 确认当前积分年度存在且状态为 `ACTIVE`。
3. 确认 `BASE_TRIP` 规则启用，并检查 `configJson`：
   ```json
   {
     "formula": "perTripPoints + actualWorkDays * perDayPoints",
     "perTripPoints": 1,
     "perDayPoints": 1
   }
   ```
4. 在 `/admin/score-rules` 检查允许队长申请的规则，例如朋友圈、小红书、复购等是否启用。
5. 在 `/admin/data-check` 先查看是否已有明显异常。

## 二、第一次导入队长数据

入口：`/admin/leaders/import`

1. 上传队长列表 Excel。
2. 检查预览结果：
   - 队长 ID、姓名、手机号是否正常；
   - 实习队长是否解析为 `INTERN`；
   - 正式队长是否解析为 `REGULAR`；
   - 冻结/暂停是否解析为 `SUSPENDED`；
   - 离职是否解析为 `LEFT`；
   - 实习队长等级展示是否为“实习”；
   - 正式队长等级是否识别为流星、彗星、恒星、星云、银河。
3. 确认导入。
4. 回到 `/admin/leaders` 检查列表。默认不显示离职队长，如需查看请选择“离职”或“全部状态（含离职）”。

注意：
- Excel 导入不会创建登录账号。
- Excel 导入不会覆盖或解除已有 `Leader.userId` 绑定。
- 有冲突的数据先不要导入，人工修正后再导。

## 三、队长注册和绑定流程

队长入口：`/leader/register`、`/leader/bind`

后台审核入口：`/admin/leader-bind-requests`

1. 队长自行注册账号。
2. 注册后进入绑定档案页。
3. 系统按注册手机号匹配未绑定队长档案。
4. 队长确认档案并提交绑定申请。
5. 管理员或队长主管在后台审核。
6. 审核通过后，队长端可查看个人档案、积分中心和申请记录。

如果匹配不到档案：
- 先检查队长注册手机号是否与导入档案手机号一致；
- 必要时在后台修改档案手机号；
- 队长重新进入绑定页提交申请。

## 四、导入销转表

入口：`/admin/trips/import`

1. 上传销转表。
2. 检查预览：
   - 路线名称、开始时间、结束时间；
   - 主队、副队、跟队解析；
   - 未匹配队长列表。
3. 点击确认导入。
4. 导入完成后回到 `/admin/trips`，新导入/更新的团期会排在前面。
5. 进入团期详情页，确认带队队长、角色、实际带队天数和完成状态。

注意：
- 销转表导入只创建/更新团期和带队记录。
- 不会自动生成积分。
- 未匹配队长不会阻塞整批导入，但需要人工补充。

## 五、核对带队队长

入口：`/admin/trips/[id]`

1. 查看团期详情。
2. 核对主队、副队、跟队角色。
3. 核对实际带队天数。
4. 已完成的带队记录需勾选“已完成”。
5. 如果队长错误，且尚未生成基础积分，可以删除带队记录后重新添加。
6. 如果已生成基础积分，不能直接删除带队记录，需要先作废对应积分。

## 六、设置团期完成状态和实际天数

入口：`/admin/trips/[id]`

1. 团期实际结束后，将状态改为 `COMPLETED`。
2. 设置每个实际带队队长的 `actualWorkDays`。
3. 勾选 `isCompleted`。
4. 对取消团设置 `CANCELLED`，取消团不会生成基础积分。

## 七、单团生成基础积分

入口：`/admin/trips/[id]`

条件：
- 团期状态为 `COMPLETED`；
- 带队记录 `isCompleted = true`；
- 实际带队天数 > 0；
- 该带队记录尚未生成基础积分；
- `BASE_TRIP` 规则启用；
- 存在覆盖团期结束日期的 ACTIVE 积分年度。

操作：
1. 点击“生成基础积分”。
2. 成功后页面显示生成结果。
3. 进入 `/admin/score-records` 可查看 `BASE_TRIP` 记录。
4. 队长端 `/leader/dashboard` 分数同步增加。

## 八、批量生成基础积分

入口：`/admin/trips`

1. 使用筛选条件定位要处理的团期。
2. 点击“批量生成当前页”。
3. 系统会跳过不符合条件、已生成、未完成、天数无效的带队记录。
4. 展开处理明细，查看生成和跳过原因。

注意：
- MVP 当前按当前页处理，跨分页批量请分批执行。
- 批量生成仍然不会重复生成已处理的带队记录。

## 九、队长申请加分

入口：`/leader/applications/new`

1. 队长选择可申请积分规则。
2. 如果规则配置 `requireTrip = true`，必须选择关联团期。
3. 填写证明材料，可上传图片证明。
4. 提交后进入申请记录。
5. 待后台审核后才会入账。

规则来源：
- 队长端只展示 `ScoreRule.configJson.allowLeaderApplication = true` 的启用 ADD 规则。
- 是否必须关联团期由 `ScoreRule.configJson.requireTrip` 控制。

## 十、后台审核加分

入口：`/admin/score-applications`

1. 查看待审核申请。
2. 打开详情，核对队长、规则、团期、证明文本和图片。
3. 审核通过：生成 `ScoreRecord`，队长积分增加。
4. 审核拒绝：填写拒绝原因，不生成积分。

注意：
- 已审核申请不能重复审核。
- 未关联团期应显示“未关联团期”。

## 十一、后台专项加分

入口：`/admin/score-adjustments/new`

1. 搜索选择队长。
2. 搜索选择启用、生效、ADD 类型的积分规则。
3. 选择积分年度。
4. 可选关联团期。
5. 填写原因和证据。
6. 提交后直接生成有效积分。

适用场景：
- 优质素材；
- 推荐队长；
- 带教新人；
- 特殊贡献；
- 历史数据补录。

所有专项加分都进入统一积分台账，可作废、可进排行榜和奖金测算。

## 十二、违规扣分

入口：`/admin/violations/new`

1. 搜索选择队长。
2. 选择扣分规则。
3. 可选关联团期。
4. 标题、说明、证据可选，但建议填写，便于后续复核。
5. 提交后生成负分 `ScoreRecord`。

注意：
- 扣分规则分值来自 `ScoreRule`。
- 扣分 `effectivePoints` 应为负数。
- 录错后不要删除记录，通过积分作废纠错。

## 十三、积分作废

入口：`/admin/score-records/[id]`

1. 找到错误积分记录。
2. 点击“作废积分”。
3. 填写作废原因。
4. 确认后状态变为 `VOIDED`。

作废影响：
- 队长端总分不再计入；
- 排行榜不再计入；
- 奖金测算不再计入；
- BASE_TRIP 作废后会解锁对应 TripLeader，允许重新生成基础积分。

## 十四、查看积分台账

入口：`/admin/score-records`

常用筛选：
- 队长；
- 积分年度；
- 分类；
- 加分/扣分；
- 状态；
- 日期范围。

台账详情可查看：
- 来源；
- 关联团期；
- 规则快照；
- 作废信息；
- 备注。

## 十五、查看排行榜

入口：`/admin/score-ranking`

排行榜用于运营核对和奖金测算前检查。

统计口径：
- 只统计 `EFFECTIVE`；
- 不统计 `VOIDED`；
- 扣分以负数计入总分；
- 带队次数按已完成团期和已完成带队记录统计。

## 十六、配置奖金池

入口：`/admin/bonus-pool`

1. 选择积分年度。
2. 输入奖金池注入标题和金额。
3. 金额必须大于 0。
4. 提交后累计到该年度奖金池。

权限：
- `SUPER_ADMIN`、`ADMIN`、`FINANCE` 可操作。

## 十七、做奖金测算

入口：`/admin/bonus-settlement`

1. 选择积分年度。
2. 生成测算预览。
3. 检查符合资格人数、总积分、封顶金额和未分配余额。
4. 保存测算结果。
5. 打开详情查看测算快照。

当前试运行规则：
- 年度带队次数 >= 8；
- 总有效积分 > 0；
- LEFT / SUSPENDED 不符合资格；
- 实习队长可参与试运营奖金测算；
- 兼职 / 全职共用一个奖金池；
- 严重投诉取消当年奖金资格；
- 红线行为在奖金测算中积分清零，并取消当年奖金资格；
- 节假日积分计入有效积分，影响排名和奖金测算，暂不设置节假日出勤硬性门槛；
- 满足基础资格的队长全部参与分配，不再限制“有效积分排名前 40%”；
- 采用档位权重法：A档前 20% 权重 1.8，B档 20%-50% 权重 1.3，C档 50%-100% 权重 1.0；
- 个人理论奖金 = 奖金池 ×（个人有效积分 × 档位权重）÷ 所有参与队长加权积分总和；
- 单人封顶 2000 元；
- 超出封顶的金额暂不二次分配。
- 队长端暂不展示个人奖金测算金额，最终奖金以公司年度结算确认为准。

## 十八、每周建议检查的数据

入口：`/admin/data-check`

每周至少检查：
1. 未绑定队长；
2. 待审核绑定申请；
3. 已完成团期未生成基础积分；
4. 团期已完成但带队记录未完成；
5. 超过 3 天待审核积分申请；
6. 积分方向和分值异常；
7. 奖金测算风险。

## 十九、出错时怎么处理

| 场景 | 处理方式 |
| --- | --- |
| 销转表导错团期 | 若无业务关联可删除；有业务关联请改为取消 |
| 带队队长导错 | 未生成积分可删除带队记录；已生成先作废积分 |
| 基础积分生成错 | 作废 BASE_TRIP 积分，修正带队记录后重新生成 |
| 申请审核错 | 作废对应 ScoreRecord，申请历史保留 |
| 违规扣分录错 | 作废扣分记录，必要时重新录入 |
| 队长离职 | 将队长状态设为 LEFT，不删除历史数据 |
| 错误队长档案 | 仅无任何业务关联时可物理删除 |

## 二十、哪些数据可以删除

可以删除：
- 无绑定账号、无带队、无积分、无申请、无违规、无奖金记录的错误队长档案；
- 无带队、无积分、无申请、无违规记录的错误团期。

不建议删除：
- 已生成积分的队长或团期；
- 已参与奖金测算的队长；
- 有申请、扣分、带队记录的业务对象；
- 任何需要审计追溯的数据。

## 二十一、进入正式运营前还需要补充的功能

1. 图片存储迁移到稳定对象存储；
2. Excel 导出；
3. 队长端消息通知；
4. 小程序正式登录与同步；
5. 申诉流程；
6. 正式奖金结算锁定；
7. 更细粒度权限；
8. 自动化回归测试；
9. 生产备份与恢复方案；
10. 运营数据看板。
