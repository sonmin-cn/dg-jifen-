# 测试账号与测试数据说明

本文用于 MVP 试运营前准备测试账号和测试数据。请不要在本文档中记录真实生产密码、真实身份证号、真实银行卡或其他敏感信息。

## 一、测试账号说明

测试密码请以本地 seed 或测试环境配置为准。文档中不写真实敏感密码。

| 角色 | 建议账号 | 主要能力 | 不能做什么 |
| --- | --- | --- | --- |
| SUPER_ADMIN | admin | 全部后台管理、删除无业务对象、作废积分、配置规则 | 不应直接修改数据库绕过审计 |
| ADMIN | admin 级测试账号 | 管理队长、团期、规则、专项加分、奖金池、测算 | 不应访问队长个人端替队长操作 |
| LEADER_MANAGER | manager | 管理队长、团期、审核申请、录入扣分、作废积分 | 不能管理积分规则、不能创建专项加分、不能删除对象 |
| FINANCE | finance | 查看台账、排行榜、奖金池和奖金测算，录入奖金池 | 不能创建扣分、作废积分、删除队长/团期 |
| EXECUTIVE_VIEWER | viewer | 只读查看关键后台数据 | 不能做任何写操作 |
| LEADER | leader 或新注册账号 | 查看本人档案、积分、提交申请、上传证明 | 不能访问管理端，不能查看其他队长数据 |
| PRODUCT_MANAGER | product 测试账号 | 本阶段不开放积分敏感功能 | 不能访问积分台账、奖金、扣分、规则等敏感页面 |

## 二、角色验收重点

### SUPER_ADMIN / ADMIN

- 可以进入 `/admin/dashboard`。
- 可以导入队长和销转表。
- 可以生成基础积分。
- 可以配置积分规则。
- 可以专项加分。
- 可以作废积分。
- 可以删除无业务关联的错误队长和错误团期。

### LEADER_MANAGER

- 可以管理队长和团期。
- 可以审核队长绑定和积分申请。
- 可以录入违规扣分。
- 可以作废积分。
- 不应能新增积分规则。
- 不应能创建专项加分。
- 不应能删除队长或团期。

### FINANCE

- 可以查看积分台账、排行榜、奖金池、奖金测算。
- 可以录入奖金池和保存测算。
- 不应能扣分、专项加分、作废积分、删除队长或团期。

### EXECUTIVE_VIEWER

- 只读查看。
- 不应看到或执行任何写操作。

### LEADER

- 登录后进入 `/leader/dashboard`。
- 未绑定时进入 `/leader/bind`。
- 绑定后只能查看自己的档案、积分和申请。
- 不能访问 `/admin`。

## 八、哪些测试数据不能删除

不要物理删除：
- 已绑定账号的队长；
- 有带队记录的队长；
- 有积分记录的队长；
- 有申请、违规、奖金测算记录的队长；
- 有 TripLeader 的团期；
- 有 ScoreRecord 的团期；
- 有申请或违规事件关联的团期；
- 已用于验收截图或试运营复盘的数据。

这些数据如需纠错，应使用：
- 队长设为离职；
- 团期改为取消；
- 积分作废；
- 重新生成基础积分；
- 重新录入扣分或专项加分。

## 九、哪些测试数据可以安全删除

可以删除：
- 无 `userId`、无 TripLeader、无 ScoreRecord、无申请、无违规、无奖金记录的错误队长；
- 无 TripLeader、无 ScoreRecord、无申请、无违规记录的错误团期；
- 未提交过业务流程的临时草稿类数据。

删除前建议先在详情页查看系统提示。只允许 `SUPER_ADMIN` / `ADMIN` 执行删除。

## 十、测试数据准备建议

1. 每次验收前先运行 `npm run mvp:check`。
2. 在 `/admin/data-check` 查看异常。
3. 每类核心流程至少保留 1 条成功数据和 1 条失败/作废数据。
4. 测试完成后不要直接清库，先导出或截图关键结果。
5. 生产试运营前，应重新导入真实队长和真实销转表，再做一次完整核对。

## 十一、安全提醒
