# 队长积分管理系统小范围内部试运行操作说明

版本：v1.0  
日期：2026-07-07  
适用阶段：CloudBase Staging / 小范围内部试运行  
建议周期：1-3 天  
当前发布提交：`60b81ba 数据访问私有读写（已验证）`

## 1. 文档目标

本文用于指导“队长积分管理系统”在正式扩大使用前完成小范围内部试运行。

试运行目标不是追求一次性覆盖所有历史业务，而是用少量真实或半真实数据，把核心链路跑顺：

1. 后台账号可以稳定登录和操作。
2. 队长端可以注册、绑定档案、提交加分申请。
3. 管理端可以导入队长、导入团期、审核加分、补录专项加分、录入扣分和作废积分。
4. 积分台账、排行榜、数据核对和奖金测算口径可被人工核对。
5. COS 凭证图片采用私有读写和后端登录态代理，未登录用户不能直接读取图片。
6. CloudBase 日志、MySQL 数据、COS 存储和问题反馈都能被持续观察。

## 2. 试运行边界

### 2.1 试运行范围

| 项目 | 建议 |
| --- | --- |
| 试运行周期 | 1-3 天 |
| 参与后台人员 | 1 名系统管理员、1 名队长主管、1 名产品/规则负责人、可选 1 名财务 |
| 参与队长 | 3-5 名已知测试队长或内部队长 |
| 数据范围 | 少量队长档案、少量团期、少量积分申请和审核数据 |
| 使用环境 | 当前 CloudBase Staging 环境 |
| 是否扩大范围 | 不扩大范围；试运行完成并复盘后再决定 |

### 2.2 暂不做的事情

1. 不开放给全部队长使用。
2. 不导入大批量历史数据。
3. 不把奖金测算结果作为正式发放依据。
4. 不在飞书、聊天或文档中记录数据库密码、完整 `DATABASE_URL`、COS/CAM Secret、`SESSION_SECRET`。
5. 不手工修改数据库字段、索引、外键和表名。
6. 不删除业务记录；错误积分统一走“作废”。
7. 不把 COS bucket 改回公有读作为长期方案。

## 5. 试运行节奏

### 5.1 Day 0：准备日

1. 确认参与人员名单。
2. 创建或确认后台账号。
3. 确认默认账号已禁用或改密。
4. 完成 MySQL 备份或导出。
5. 确认 COS bucket 是私有读写策略。
6. 确认 CloudBase 当前部署版本对应提交 `60b81ba` 或后续确认版本。
7. 准备 3-5 名试运行队长档案。
8. 准备 2-3 条试运行团期。
9. 在飞书建立问题记录表或直接在本文“问题记录模板”中记录。

### 5.2 Day 1：跑通核心链路

建议顺序：

1. 管理员登录后台。
2. 导入或手工确认队长档案。
3. 队长注册账号。
4. 队长提交绑定申请。
5. 后台审核绑定申请。
6. 导入或创建团期。
7. 设置团期完成状态和实际带队天数。
8. 生成基础积分。
9. 队长提交加分申请并上传图片证明。
10. 后台审核加分申请，确认图片能显示。
11. 查看积分台账和队长端总分。

### 5.3 Day 2：覆盖异常和纠错

建议覆盖：

1. 加分申请拒绝。
2. 专项加分补录。
3. 违规扣分。
4. 积分作废。
5. 作废后排行榜和队长端积分变化。
6. 数据核对页异常提示。
7. 无权限账号访问后台页面。
8. 未登录访问图片代理。

### 5.4 Day 3：复盘和生产化判断

建议产出：

1. 问题清单按 P0/P1/P2 分级。
2. 确认是否还有阻塞正式试用的问题。
3. 确认数据是否需要清理、保留或归档。
4. 确认是否进入更大范围试用。
5. 确认是否需要正式域名、监控告警、备份周期和权限细分。

## 6. 每日操作流程

### 6.1 每天开始前

| 检查项 | 操作 | 预期结果 |
| --- | --- | --- |
| 登录页 | 打开 `/login` | 页面正常加载 |
| 管理后台 | 管理员登录 `/admin/dashboard` | 能进入后台 |
| 队长端 | 试运行队长登录 `/leader/dashboard` | 能进入队长首页 |
| CloudBase 日志 | 查看最近错误日志 | 无连续 5xx、数据库认证失败、COS 403 异常 |
| 图片代理 | 后台打开一条带图片申请详情 | 图片显示正常 |
| 数据核对 | 打开 `/admin/data-check` | 页面无报错，异常可解释 |

### 6.2 每天进行中

1. 每完成一条业务链路，在问题记录表中写“通过/异常”。
2. 所有异常先截图并记录时间、账号角色、页面路径、操作步骤。
3. 不要反复点击提交按钮制造重复数据。
4. 发现 P0 问题立即暂停相关操作。
5. 不在数据库中直接修改业务记录，除非技术支持明确给出 SQL 并记录原因。

### 6.3 每天结束后

1. 导出或截图当天问题清单。
2. 查看 CloudBase 最近日志。
3. 抽查 `ScoreRecord` 台账与队长端总分是否一致。
4. 抽查 COS 图片匿名访问是否仍不可读。
5. 记录当天结论：继续 / 暂停 / 结束。

## 7. 功能操作说明

### 7.1 管理端登录

入口：`/login`

步骤：

1. 使用已确认的管理员账号登录。
2. 登录成功后进入 `/admin/dashboard`。
3. 点击退出或关闭浏览器后重新访问后台，确认登录态行为正常。

通过标准：

- 正确账号可登录。
- 禁用账号不可登录。
- 非后台角色不能进入后台管理页。

### 7.2 队长档案导入或确认

入口：`/admin/leaders/import`、`/admin/leaders`

步骤：

1. 准备少量试运行队长数据。
2. 上传队长 Excel 或使用已有档案。
3. 检查手机号、真实姓名、状态、等级。
4. 确认导入后回到列表查看。

通过标准：

- 队长档案存在。
- 手机号与试运行队长注册手机号一致。
- 离职队长默认不影响试运行。

注意：

- 导入队长档案不会自动创建登录账号。
- 已绑定的 `Leader.userId` 不应被导入覆盖。

### 7.3 队长注册与绑定

队长入口：`/leader/register`、`/leader/bind`  
后台入口：`/admin/leader-bind-requests`

步骤：

1. 队长使用试运行手机号注册账号。
2. 注册后进入绑定页。
3. 系统按手机号匹配未绑定队长档案。
4. 队长提交绑定申请。
5. 后台审核通过或拒绝。
6. 审核通过后，队长重新进入 `/leader/dashboard`。

通过标准：

- 审核通过后队长可以看到自己的档案和积分入口。
- 拒绝后有明确状态和原因。

常见问题：

- 手机号不一致：先修正队长档案手机号。
- 已有待审核申请：不要重复提交，先处理旧申请。

### 7.4 团期导入与维护

入口：`/admin/trips/import`、`/admin/trips`、`/admin/trips/[id]`

步骤：

1. 导入少量销转表或手工创建团期。
2. 检查路线、开始时间、结束时间、团期状态。
3. 检查主队、副队、跟队是否匹配。
4. 对已结束团期设置 `COMPLETED`。
5. 设置实际带队天数和完成状态。

通过标准：

- 团期列表可见。
- 团期详情能查看带队队长。
- 未匹配队长有清晰提示。

### 7.5 基础积分生成

入口：`/admin/trips/[id]`、`/admin/trips`

生成条件：

1. 团期状态为 `COMPLETED`。
2. 带队记录 `isCompleted = true`。
3. 实际带队天数大于 0。
4. `BASE_TRIP` 规则启用。
5. 团期结束日期落在 `ACTIVE` 积分年度。
6. 该带队记录尚未生成基础积分。

步骤：

1. 在团期详情点击生成基础积分。
2. 查看生成结果。
3. 到 `/admin/score-records` 查找对应积分。
4. 队长端 `/leader/dashboard` 查看总分变化。

通过标准：

- 不重复生成。
- 分值符合当前规则。
- 队长端总分同步变化。

### 7.6 队长提交加分申请

入口：`/leader/applications/new`

步骤：

1. 队长选择允许申请的加分规则。
2. 如规则要求关联团期，则选择对应团期。
3. 填写证明说明。
4. 上传 1-3 张 JPG/PNG/WEBP 图片。
5. 提交申请。
6. 在 `/leader/applications` 查看申请状态。

通过标准：

- 图片上传成功。
- 提交后状态为待审核。
- 队长申请列表能看到申请记录。

图片要求：

- 单张不超过 5MB。
- 总数不超过 3 张。
- 不上传无关私人敏感图片。

### 7.7 后台审核加分申请

入口：`/admin/score-applications`、`/admin/score-applications/[id]`

步骤：

1. 打开待审核申请。
2. 核对队长、规则、团期、文字证明和图片证明。
3. 打开页面开发者工具 Network，可筛选 `evidence-images`。
4. 确认图片请求走 `/api/evidence-images/...`。
5. 选择通过或拒绝。
6. 拒绝时必须填写明确原因。

通过标准：

- 审核通过后生成 `ScoreRecord`。
- 审核拒绝后不生成积分。
- 图片在登录态下正常显示。
- 图片不通过 COS 原始公开链接展示。

### 7.8 专项加分

入口：`/admin/score-adjustments/new`

适用场景：

- 节假日贡献。
- 推荐新队长。
- 带教新人。
- 特殊贡献。
- 历史补录。

步骤：

1. 选择队长。
2. 选择启用且生效的加分规则。
3. 选择积分年度。
4. 可选关联团期。
5. 填写原因和证据。
6. 可上传图片证明。
7. 提交后查看台账。

通过标准：

- 提交后直接生成有效积分。
- 台账详情能查看规则快照和证据。
- 图片走后端代理。

### 7.9 违规扣分

入口：`/admin/violations/new`

步骤：

1. 选择队长。
2. 选择扣分规则。
3. 可选关联团期。
4. 填写标题、说明、证据。
5. 提交后查看积分台账。

通过标准：

- 生成负分 `ScoreRecord`。
- 队长端积分减少。
- 排行榜分数同步变化。

### 7.10 积分作废

入口：`/admin/score-records/[id]`

步骤：

1. 打开一条有效积分记录。
2. 点击作废。
3. 填写作废原因。
4. 确认后刷新台账、排行榜和队长端。

通过标准：

- 记录状态变为 `VOIDED`。
- 队长端总分不再计入该记录。
- 排行榜和奖金测算不计入作废记录。
- `BASE_TRIP` 作废后允许重新生成对应基础积分。

### 7.11 积分台账与排行榜

入口：`/admin/score-records`、`/admin/score-ranking`

检查项：

1. 按队长筛选台账。
2. 按年度筛选台账。
3. 查看加分、扣分、作废状态。
4. 查看排行榜总分。
5. 对比队长端总分。

通过标准：

- 只统计 `EFFECTIVE`。
- `VOIDED` 不计入。
- 扣分以负数计入。
- 页面筛选和详情跳转正常。

### 7.12 数据核对

入口：`/admin/data-check`

检查项：

1. 未绑定队长。
2. 待审核加分申请。
3. 未生成基础积分的已完成团期。
4. 积分异常。
5. 奖金测算风险。

通过标准：

- 页面无报错。
- 异常说明能指导下一步处理。
- 跳转链接可打开。

### 7.13 奖金池和奖金测算

入口：`/admin/bonus-pool`、`/admin/bonus-settlement`

试运行要求：

1. 可以配置小额测试奖金池。
2. 可以生成测算预览。
3. 可以保存测算结果。
4. 不把试运行测算作为正式发放依据。

通过标准：

- 奖金池金额累计正确。
- 作废积分不计入测算。
- 离职、暂停、严重投诉、红线行为等资格规则可被识别。
- 单人封顶和未分配余额展示合理。

## 8. COS 私有读写和图片代理验收

这是本轮试运行必须保留的安全检查。

### 8.1 正向检查：登录后能看图

1. 使用管理员账号登录。
2. 打开一条带图片的申请详情页。
3. 图片应正常显示。
4. Network 中图片请求路径应包含 `/api/evidence-images/`。
5. 响应状态应为 200。

### 8.2 反向检查：未登录不能看图

1. 复制一条 COS 原始图片链接。
2. 用无痕窗口打开。
3. 预期：打不开，或返回 `AccessDenied`。
4. 复制一条 `/api/evidence-images/...` 代理链接。
5. 用无痕窗口打开。
6. 预期：不直接显示图片，应提示未登录或返回 401。

### 8.3 禁止行为

1. 不把 COS 原始链接发到群里。
2. 不把 `/api/evidence-images/...` 代理链接当作公开图片链接使用。
3. 不为了看图方便把 bucket 改为公有读。
4. 不下载队长证明图片到非安全位置。

## 9. CloudBase 和数据监控

### 9.1 CloudBase 云托管日志

每天至少检查两次：

| 关注项 | 异常表现 | 处理 |
| --- | --- | --- |
| 5xx 错误 | 页面报错、接口失败 | 记录时间和路径，交技术支持 |
| Prisma 连接错误 | 数据库认证失败、连接超时 | 暂停相关操作，检查数据库账号和网络 |
| COS 错误 | 上传失败、403、InvalidAccessKeyId | 检查 CAM 权限和环境变量 |
| 图片代理错误 | `/api/evidence-images/...` 返回 401/403/404/500 | 区分未登录、无权限、对象不存在和服务异常 |
| 构建/启动错误 | 新版本无法访问 | 回退到上一个可用版本或暂停试运行 |

### 9.2 MySQL 数据检查

每天结束后抽查：

1. `User` 是否出现异常新增账号。
2. `Leader` 绑定关系是否正确。
3. `ScoreApplication` 状态是否符合审核结果。
4. `ScoreRecord` 是否存在重复基础积分。
5. `AuditLog` 是否有关键操作记录。

不要直接改表数据；若必须修复，先记录原因、SQL、执行人和执行时间。

### 9.3 成本观察

小范围试运行原则上不新增云服务。

仍需观察：

1. CloudBase 云托管访问量。
2. COS 请求量和存储量。
3. 图片代理带来的云托管流量。
4. MySQL 规格和连接数。
5. 日志存储保留策略。

如果要引入正式域名、监控告警、CDN 鉴权、更高规格数据库或更长日志保留，必须先按当前腾讯云控制台价格重新评估。

## 10. 问题分级和处理

### 10.1 分级标准

| 等级 | 定义 | 处理时限 | 示例 |
| --- | --- | --- | --- |
| P0 | 阻断试运行或有安全风险 | 立即暂停相关操作，当天修复或回滚 | 无需登录可看凭证图片；管理员无法登录；积分大面积错算 |
| P1 | 影响核心链路，但有临时绕行方式 | 试运行期内修复或明确方案 | 某类申请审核失败；团期导入部分失败；图片偶发加载失败 |
| P2 | 不影响主流程，可后续优化 | 进入迭代 backlog | 文案不清晰；列表筛选不够方便；导出格式希望优化 |

### 10.2 问题记录模板

| 字段 | 填写说明 |
| --- | --- |
| 编号 | TRIAL-001 |
| 发现时间 | 例如 2026-07-07 10:30 |
| 发现人 | 姓名 |
| 角色 | 管理员 / 队长主管 / 财务 / 队长 |
| 页面路径 | 例如 `/admin/score-applications/xxx` |
| 操作步骤 | 1、2、3 分步写清楚 |

| 预期结果 | 应该发生什么 |
| 截图/日志 | 附件或日志时间点 |
| 等级 | P0 / P1 / P2 |
| 负责人 | 谁处理 |
| 当前状态 | 待处理 / 处理中 / 已修复 / 已验证 / 暂不处理 |
| 处理结论 | 修复方式或暂不处理原因 |

### 10.3 P0 暂停条件

出现以下任一情况，立即暂停扩大使用：

1. 未登录用户可直接读取凭证图片。
2. 普通队长可访问后台页面。
3. 非管理员可审核或作废他人积分。
4. 数据库认证或连接持续失败。
5. 基础积分重复生成且无法通过作废纠正。
6. 审核通过后台账未生成或队长总分严重错误。
7. 任何密钥、密码或完整连接串被发到群里或写入文档。

## 11. 回滚和恢复

### 11.1 代码回滚

当新版本出现 P0 问题时：

1. 暂停试运行操作。
2. 保留错误截图和 CloudBase 日志时间点。
3. 在 CloudBase 云托管中回退到上一个已知可用版本。
4. 回退后重新验证登录、后台首页、队长端和图片代理。
5. 记录回滚时间、回滚版本和原因。

### 11.2 数据恢复

只有在以下情况考虑恢复数据库备份：

1. 大量核心业务数据误写入。
2. 无法通过作废、补录或手工纠错恢复。
3. 技术支持和试运行负责人共同确认恢复成本低于人工修复。

恢复前必须确认：

1. 备份时间点。
2. 会丢失哪些试运行数据。
3. 是否已经通知所有参与人员。
4. 是否保留当前错误数据快照用于排查。

## 12. 试运行通过标准

1. 连续 1-3 天核心流程无 P0。
2. 所有 P1 均已修复、绕行或有明确上线前处理计划。
3. 试运行人员能独立完成日常操作，不依赖技术人员现场指导。
4. 队长端申请、图片上传、后台审核、积分入账、作废、排行榜均能闭环。
5. COS 私有读写和后端代理验证通过。
6. MySQL 已有可用备份和恢复说明。
7. 账号、权限和默认账号风险已收口。
8. CloudBase 日志无持续异常。
9. 已形成问题清单和下一阶段计划。

## 13. 试运行结束复盘

试运行结束后，负责人组织一次 30-60 分钟复盘。

复盘议题：

1. 哪些流程已跑通。
2. 哪些流程仍依赖人工判断。
3. P0/P1/P2 问题数量和状态。
4. 是否需要清理试运行数据。
5. 是否允许扩大到更多队长。
6. 是否需要正式域名和更严格权限策略。
7. 是否需要固定备份周期和监控告警。
8. 下一次发布前必须完成的事项。

## 16. 禁止清单

1. 禁止在飞书文档中写真实密码、完整连接串和 Secret。
2. 禁止把 COS 原始图片链接发到群聊。
3. 禁止为了临时验收把凭证图片长期设为公有读。
4. 禁止在生产或试运行库执行 `seed:test`。
5. 禁止直接删除积分台账、申请记录、团期和队长档案。
6. 禁止绕过系统在线下口头加分或扣分。
7. 禁止未备份就做大批量导入或修复 SQL。
8. 禁止在 P0 未解决时扩大试运行范围。
